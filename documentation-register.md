## Versioning Rules

- `Document version` tracks the approved baseline, not every saved edit. Use `Not baselined` until the first approval.
- First approval is version `1.0`. Editorial-only changes do not increment the baseline. Changes to acceptance criteria or validation rules within the same outcome and scope are minor (`1.0` to `1.1`); materially changing target users, outcome, or scope is major (`1.1` to `2.0`).
- While a previously approved document is In Review, retain its current baseline version. Assign the next version only after validation and approval.
- `/validate` proposes the next version and rationale after the document passes its approval checks. The user must confirm the version before it is applied; declining leaves the document In Review.
- If requested, a pending proposal is recorded in the document's **Pending Baseline Proposal** section and does not appear as an approved baseline until confirmed and approved.
- Keep English and French documents at the same status and baseline version. Update this register whenever an active-work item starts or ends or an approval changes a baseline.
